# Task Breakdown

围绕交付物拆分任务，不按抽象主题堆叠清单。

## 拆分方法

对目标依次回答：

1. 最终需要交付哪些文件、链接或可见结果。
2. 每个结果依赖哪些输入和前置步骤。
3. 哪些步骤可以独立验证。
4. 哪些操作会写入外部系统或难以恢复。
5. 失败后应从哪个检查点继续。

## 任务字段

每个任务尽量包含：

- 动作：以动词开头，说明要做什么。
- 输入：需要的文件、参数或权限。
- 输出：完成后出现的可见结果。
- 依赖：必须先完成的任务。
- 验收：可以客观判断成功的条件。
- 风险：敏感数据、外部写入或不可逆操作。

## 粒度规则

- 一个任务只产生一个主要结果。
- 能在一次专注执行中完成。
- 验收失败时能定位到具体步骤。
- 不把“继续完善”“做好优化”作为独立任务。
- 不为了让清单显得完整而增加没有产出的步骤。

## 排序

优先执行只读检查、接口验证和安全样例。把真实写入、公开发布和删除操作放到最后，并设置明确授权门槛。
